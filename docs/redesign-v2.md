# 新版方案：轨迹天气窗口（v2）

2026-10-15 用户确认。本文是 Round 11 起产品改版的依据；实现细节以代码与测试为准。

## 定位

面向已经有轨迹的徒步者（两步路 / 六只脚 / 奥维导出）：**出发前判断哪天、几点出发，沿途哪一段会遇到什么天气**。
不再以“地图找线”为核心——国内 OSM 徒步数据稀疏、Overpass 海外镜像国内不可达，外部平台无合规接口。

## 信息架构

底部导航：行程（首页） / 地图 / 设置。

| 页面 | 内容 |
| --- | --- |
| 行程（首页） | 导入、收藏、手绘线路列表；每条显示最佳出发窗口或主要风险；导入为第一入口；徒步星球经典线作为“示例线路”置底 |
| 线路详情 · 出发窗口 | “日期 × 出发时刻”格子图，每格 = 该时刻出发时沿途最差天气；点开看原因与来源 |
| 线路详情 · 沿途时间线 | 按天拆分；节点显示 ETA、海拔、天气；地图自动适配全程、可缩放；海拔剖面 |
| 地图（次要） | 只叠加用户自己的线路；定位只移动地图，天气为角标，长按任意点查天气 |

降级 / 移除：“搜索此区域”（隐藏，代码保留）；跳转百度的外部攻略（移除，改为“用 TrailWeather 打开”引导）。

## 已确认的决定

1. **出发窗口默认阈值**（设置中可调）：

   | 指标 | 黄 | 红 |
   | --- | --- | --- |
   | 阵风 | ≥ 13.9 m/s（7 级） | ≥ 17.2 m/s（8 级） |
   | 小时降水 | ≥ 2 mm/h | — |
   | 气温 | — | ≤ -10 ℃ |
   | 到达时间 | 晚于日落 | — |

   缺失数据不计为安全：某格关键变量缺失时显示“信息不足”，不着绿色。
2. **地形底图用天地图**：需用户在天地图开放平台注册免费 key（不可代注册，登记 blocker）；拿到 key 前此项后置。
3. **多日拆分**：优先按“营地”航点切分；无营地航点时按每天约 8 小时行走估算切分，并明确标注为估算；用户可在线路上手动调整分段点。

## 推进顺序

1. 体验修复（进行中）：定位不依赖 GMS、定位不自动弹窗、线路自动适配缩放、隐藏无效入口。
2. 首页改版 + 导航重构 + “用 TrailWeather 打开”（Android intent-filter / iOS document types）。
3. 出发窗口（复用现有天气数据与配速模型，无新数据源）。
4. 多日拆分 + 高山指标（Open-Meteo 增加冻结高度、CAPE 等字段，补 fixture）。
5. 离线包、地形底图、官方预警（和风预警接口）→ Pro 真实权益；之后才是支付与上架（需用户授权）。

## 真实性约束（沿用 AGENTS.md 红线）

- 格子颜色是阈值规则的结果，不是“安全评分”；文案写“按阈值”，不写“安全”。
- ETA、按天拆分、海拔修正、冻结高度判断均标注为估算。
- 每格可追溯到来源与时次；预报非实测。
