# 多角色审查（2026-10-16）

目的：跳出“功能是否齐全”的框架，换几个角色审视山晴（TrailWeather），为明天的 UI 重构和第一个 beta 定方向。
每条结论后标注状态：**已修**（本轮 Round 26 已完成）、**明日**（UI 重构批次）、**beta 前**（发布前必须完成）、**待决策**（需要产品负责人拍板）、**以后**。

基线：`feat/robust-track-import` @ Round 25；97 个 Dart 文件、约 2.16 万行；50 个测试文件、297 个测试通过。

---

## 0. 一句话结论

山晴目前是一个**诚实的数据浏览器**：来源、时刻、缺失都标得很清楚；
但用户打开它是想要一个**出发决策**（“明天走不走、几点走、哪段危险”）。
数据诚实是护城河，**把诚实的数据翻译成可执行的判断**是下一阶段的主线。
UI 平庸是这个矛盾的外在表现：页面在罗列数据，而不是在回答问题。

## 5. 户外公司高管（商业）

- **护城河薄**：天气数据都来自公开模型，谁都能接入。能沉淀的是：对徒步场景的**解释能力**（山脊风、海拔订正、出发窗口）、用户的线路库、以及“用山晴打开”带来的分发。
- **变现路径**（都依赖先有可信的决策能力）：
  1. 俱乐部／领队 B2B：一次分享给全队的行前天气简报（分享图已是雏形）。
  2. 户外保险：出发前天气风险报告作为附加材料。
  3. 装备导购：按沿途最低气温、降水推荐装备（需谨慎，避免损害“数据诚实”的定位）。
- **建议**：beta 阶段不谈付费，先验证两个指标：导入后 7 日复访率，以及分享图带来的新安装。

## 7. UI 重构方向（明日）

1. **先做 design tokens**：颜色、间距、圆角、字号集中定义，替换 28 处硬编码颜色，深色和浅色一起验收。
2. **山晴自己的视觉签名：“山脊天气带”**。把海拔剖面作为主视觉，沿剖面用色带标出风、雨、冷、天黑的路段。详情页、出发窗口、分享图共用这一套语言。
3. **配色从“通用 Material 蓝”换成“山与天”**：天空蓝、岩石灰、植被绿，配一个警示橙；红色只用于真正触发阈值的情况。
4. **结论先行**：顶部一句判断，配信心或一致度和最关键的一个风险，数据放在下层。
5. **信心可视化**：多个来源一致时实心，分歧时虚化或显示区间，替代纯文字说明。

## 9. 本轮已修清单（Round 26）

- 签名与包名：`tool/configure_release.py`（applicationId / Bundle ID、按环境变量启用正式签名）、`tool/create_android_keystore.sh`（本人运行；生成 PKCS12、上传 4 个 Secrets、打印指纹与公钥）；CI 解码签名文件、只在 APK 步骤暴露密码、用 apksigner 记录证书指纹，配置了正式签名却打出 debug 签名时失败；`verify_build_branding.py` 校验 APK 与 iOS 的应用 ID。
