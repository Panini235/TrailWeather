# 出发窗口

山晴的线路详情页现在先显示选定时刻的天气摘要和获取时间，再显示地图。点击“比较出发窗口”可以比较 1、3 或 5 天，每天从选定时间开始、每隔两小时、最多五个出发时刻。点开格子可查看依据，再应用该时间返回行程模式。当前方向、配速和航点停留保持不变；更改所选来源会一起带回详情。

## 颜色和缺口

默认规则来自 `redesign-v2.md`：阵风至少 13.9 m/s 为黄、至少 17.2 m/s 为红，小时降水至少 2 mm 为黄，气温至多 −10℃ 为红，预计到达晚于日落为黄。在设置或比较页可修改前四个数值；必须为有限数值、黄色阵风小于红色。偏好保存在本机，不需要登录。

每格是所选单一来源在预计经过时段内的最严重规则结果，不是安全评分。不用持续风速替代阵风，不用降水概率替代降水量，也不把缺失值补为零。未知值、非有限值、不完整节点映射、实际预报时段以外、缺日落、旧缓存或刷新失败均保留信息不足。已知红/黄原因与数据缺口可以同时出现。官方预警与日出尚未接入。

## 时间、空间和日落

- 所有界面时间明确按设备时区显示，跨时区出行须自行核对。计算内部使用 UTC。
- ETA 使用现有配速模型，包含轨迹爬升/下降、分摊休息和航点停留。海拔缺失会注明 ETA 未计入相应地形影响。
- 每段在预计经过的每个小时检查两端天气，属于保守的空间和小时近似。不能把采样密度当作预报精度，也不能把共享查询网格当成多个独立证据。
- 在整点抵达终点时额外检查该时刻气温，不把抵达之后整小时的累计降水或最大阵风纳入行走途中。
- Open-Meteo 原始降水量与最大阵风字段表示原始时次**之前一小时**，与瞬时气温不同。出发窗口将这些值对齐经过小时，并在依据页保留每个变量的原始有效时次。2026-10-16 已核对官方文档 `https://open-meteo.com/en/docs` 的 Hourly Weather Variables 表。没有改变或伪造来源原始记录。
- 日落取来源提供的终点日落。为避免设备在异地、UTC 日切或已过日落后误选到次日日落，以终点经度近似归属太阳日期。这是日期归属近似，不是线路时区识别或日落算法。未考虑山体遮挡、日出或极昼/极夜；没有日落记录时显示信息不足。
- 跨夜另有提示；超过 24 小时的连续行走不生成比较结果，提示先提供单日路线。多日拆分仍属于 T-147，不能以连续步行估算冒充营地行程规划。

## 请求和断网

所有未来格子合并成一个查询时间窗，使用现有天气仓库的批量、网格去重和缓存机制；“一次联合查询”不等于所有来源只发一个 HTTP 请求。请求身份包括来源、坐标顺序、海拔与时间窗。修改阈值只在本机重算，不重建来源或重复请求；按次来源禁止进入批量比较。

前台按现有天气时钟检查时效，离开应用停止轮询；主动刷新失败时保留旧数据和真实获取时间。出发窗口缓存可以在已有数据时用于查看，但不能替代独立的离线行程包。用户仍需在详情页主动下载离线包。

## 本轮其他修正

- 旧节点分类不再把持续风速当作阵风使用。
- 详情摘要缺气温时显示“此来源未提供”，不再显示虚构的 0℃。
- 详情的日落提醒复用出发日期匹配逻辑，避免“日落后出发”漏掉提醒。
- 天气摘要与获取时间放在详情首屏；出发比较的说明放在表格下方。
- 低耗电设置文案修正为实际行为：加大间距，常规节点上限 12，关键航点保留；前台仍检查时效。

验证记录见 `verification/departure-2026-10-16/`。Flutter widget 测试检查共享界面，Android/iOS 构建检查平台编译；它们不能证明真机的启动速度、耗电、GPS 和飞行模式冷启动。
