# 离线行程包

山晴的基础离线包保存线路、航点、当前方向、配速、计划时刻、节点预计到达时间和一个天气来源返回的全部预报。它与普通天气缓存分开存放，清理普通缓存不会删除离线包。

## 出发前使用

1. 在线打开线路，选好日期、方向和天气来源；需要预计到达时间时切换到行程模式并调整配速。
2. 点击右上角「下载离线行程包」，选择从当前计划时刻所在小时开始的 24、48 或 72 小时。
3. 点击「下载并校验」。下载后自动进入离线查看页，核对获取时间、覆盖缺口和温度/降水量/持续风速的可用情况。没有任何有效数值时不会保存。
4. 从首页「离线行程包」可重新进入。选择时刻查看逐节点天气，或使用下载时保存的预计到达时间。时间采用设备时区；来源时区与原始 UTC 时间保存在溯源中。
5. 出发前手动联网更新，随后关闭网络并重新打开 App 检查所需时段。正式户外使用前仍需完成 iOS/Android 真机飞行模式验收。

## 状态的含义

- **所选时段均有数据**：每个节点的每个小时至少有一个气象数值；不表示每个指标都齐全。核心三项齐全的数量另列，缺失始终显示「此来源未提供」。
- **覆盖不全**：节点小时存在缺口。不会以相邻小时或其他地点补齐；不能据此判断安全。
- **旧预报**：按原始获取时间和来源建议更新间隔判断，不以保存包的时间重置新鲜度。
- **行程时段已结束**：旧包可继续回看，下一次行程应重新下载。
- **校验失败**：不显示损坏包中的天气。可删除损坏包，再从原线路下载；其他离线包仍可查看。

下载和更新均由用户主动触发。更新失败、零可用覆盖或覆盖数量减少时保留旧包，支持重新尝试。离线页本身不会初始化天气仓库、请求地图瓦片或读取 GPS。

## 存储与包含范围

- iOS/Android：应用文档目录 `offline_trips_v1/`。先写同目录临时文件、flush、读回逐字核对，再 rename 替换正式文件。不使用普通缓存 LRU；卸载 App 会删除本机副本。系统备份行为取决于系统设置。
- 完整性：带版本、UTF-8 长度和 CRC32 的封装；读取时再验证节点与路线、查询坐标、时次和来源身份。CRC32 仅检测意外损坏，不是密码学签名或来源认证。
- 每包上限 64 MiB；没有自动淘汰离线包，需要用户自行删除。不保存账号或天气服务 Key。
- Web：仅作为工程验证端，使用独立的浏览器存储键。存在配额/清除站点数据风险，不保证网页断网冷启动；没有将其作为可发布 PWA。实际断网浏览还观察到 Noto 中文备用字体加载失败，详见浏览器控制台证据。
- 来源目前限 Open-Meteo 两个已接入模型及 MET Norway；其他来源的离线范围复核、按次来源的费用确认仍未完成，因此不开放批量下载。
- 保存完整返回时次、日落、数据类型、请求/返回坐标、模型信息、原始获取/起报时间、许可和署名。相邻节点共享近似网格时仍显示原有说明。
- 本地绘制线路示意图，保留不连续段；**没有离线底图、实时定位导航、节点照片打包或官方预警**。示意图不请求地图服务。
- 快照保留现有行程参数，尚未实现可编辑的多日营地计划和徒步进度跟踪，T-147 继续开放。

## 验证边界

`test/unit/offline_trip_test.dart` 验证文件存储重建、24/48/72 小时和跨午夜读取、普通缓存清除/LRU、全量溯源、部分覆盖、错误坐标、损坏检测、失败保留与重试。`test/widget/offline_screens_test.dart` 验证首页入口、下载重试、禁止天气访问的离线查看、360px 双倍字体及深浅色布局。

这些自动化验证不替代原生安装包的飞行模式冷启动、系统强制结束进程、设备低存储或升级/恢复测试。最终构建及浏览器证据见 `docs/verification/offline-2026-10-16/`。
